Shape-Agnostic Focus Obscuration Analysis

Eliminating false positives in WCAG 2.4.11 / 2.4.12 detection for non-rectangular elements

RQ: Does shape-agnostic grid probing correctly classify WCAG 2.4.11/2.4.12 obscuration for non-rectangular focusable elements where bounding-box-based probing fails?
Focusable Element
Any non-rectangular focusable UI component
(circular, rounded, clipped, multi-line)
Phase 1 — Algorithm Design
Step A — Shape Classification
Circular / Oval
Corners of the bounding box fall outside the circle — excluded from probing
border-radius: 50%
Rounded Corners
Corner areas cut by the radius curve — points there belong to the background
border-radius
Multi-line Text
Link wraps across lines — the gap between lines and the short last line are not part of the element
getClientRects()
Custom Clip
Element is masked to a polygon or custom path — points outside the mask boundary are ignored
clip-path
Rendered Shape Boundary
The actual area of the element — known per shape type
Step B — Shape-Agnostic Probing
1
Generate uniform 7×7 grid across bounding box
2
Test each point — is it inside the rendered shape?
3
Skip points outside the shape boundary
4
Check remaining points for overlapping content
5
Obscuration = hidden shape points ÷ total shape points
